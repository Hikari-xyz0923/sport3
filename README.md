# 知动乎 · 海淀区匹配平台

这是根据《海淀区体育搭子匹配平台产品说明书》制作的可运行平台，前端使用 HTML/CSS/JavaScript，后端使用 Node.js 内置 HTTP 模块。

## 使用方式

网页内容不在 `.bat` 文件里：`start-server.bat` 只是启动器，真正的动态网页由 `index.html`、`styles.css` 和 `app.js` 组成。

推荐双击 `open-website.bat`。它会启动 Node.js 网站服务并自动打开浏览器；也可以双击 `start-server.bat`，然后访问 `http://127.0.0.1:8080`。服务基于 Node.js 内置 HTTP 模块，不需要安装第三方依赖。

## 已实现的产品说明书功能

- 发现页：推荐搭子卡片、匹配分、共同运动、水平/时间/距离/区域信息
- 搜索与筛选：昵称、运动类型、水平等级、距离范围
- 列表/地图视图切换，地图位置使用区域中心点保护隐私
- 搭子详情弹窗与双向匹配请求状态
- 发布寻找搭子需求，发布后同步到“我的”活动记录
- 消息中心：匹配请求、同意/暂不考虑、聊天窗口与首次见面安全提示
- 我的：实名认证状态、运动标签、数据统计、活动记录、评价展示
- 响应式布局：桌面侧边栏与移动端底部导航

现在已支持真正的用户登录与注册，不再使用固定演示数据：用户名和密码会保存到服务器端 `data.json`（密码以加盐哈希保存），个人资料、发布需求、匹配请求也按用户保存。

首次使用请注册一个账号，然后完善“我的”页面资料；用另一个账号登录即可看到前一个账号公开的资料并发起匹配。

当前是本地开发版，`data.json` 是本地轻量数据文件。正式上线时建议替换为 PostgreSQL/MySQL，并增加短信验证、密码找回、HTTPS、限流和正式会话存储。

## 部署到云端

项目已经提供 `Dockerfile`、`docker-compose.yml` 和 `render.yaml`，可以直接部署到 Render、Railway、Fly.io 或任意支持 Docker 的云服务器。

### Render（推荐的最短路径）

1. 将 `D:\` 下的项目文件上传到一个 GitHub 仓库（至少包含 `index.html`、`styles.css`、`app.js`、`server.js`、`Dockerfile`、`render.yaml`）。
2. 在 Render 选择 **New → Blueprint**，连接该仓库并部署。
3. 部署完成后，Render 会生成一个 `https://...onrender.com` 地址，其他设备直接访问即可。
4. `render.yaml` 已配置 `/health` 健康检查和 `/data` 持久化磁盘；不要删除这个磁盘，否则用户数据会丢失。

### 任意 Docker 云服务器

在项目目录执行：

```bash
docker compose up -d --build
```

然后将云服务器的 8080 端口通过域名或反向代理（建议 HTTPS）暴露出去。生产环境请将 `COOKIE_SECURE=true` 保持开启，并把 `/data` 挂载到持久化磁盘。

当前版本的账号、资料、匹配和聊天数据保存为 `/data/data.json`。会话保存在进程内存中，服务重启后需要重新登录；如果未来扩展到多实例，需要把会话迁移到 Redis，把业务数据迁移到 PostgreSQL/MySQL。

## 让局域网设备访问

本地启动方式默认只绑定 `127.0.0.1`，适合本机演示。若要临时让同一局域网设备访问，可使用 `HOST=0.0.0.0 node server.js`，并在防火墙中放行 8080 端口；公网使用请优先采用上面的 Docker 部署并配置 HTTPS。
